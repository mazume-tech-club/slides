01DOMとは

DOMは、要素の家系図です

DOM（Document Object Model、文書を部品の木で表す仕組み）は、ブラウザがHTMLを読んで作る家系図です。 タグが親で、中のタグが子です。

  • 01画面は、この木を見て描きます。
  • 02JavaScriptが探すのも、HTMLの文字列ではなく、この木です。
  • 03木の点ひとつを、ノード（node、木の点）と呼びます。

01DOMとは

このHTMLは、こう木になります

<body>
  <p class="note">こんにちは</p>
</body>

文字列を部品に分ける作業を、パース（parse、部品に分けること）と呼びます。中の文字も点です。

01DOMとは

追加すると末尾に1行、クリックで線が付きます

const list = document.querySelector("#notes"); // リストを探す
const item = document.createElement("li"); // 空の箱を作る
item.textContent = "新しい行"; // 文字として入れる
list.appendChild(item); // 末尾の子につなぐ
  • 最初からある行
  • もう1行

空のままでは増えません。行のクリックは、親のリストがまとめて聞いています。

02画面の描き方

木ができてから、画面になります

  • 01DOMと CSSOM（CSS Object Model、スタイルの木）を作ります。
  • 02箱になるものだけを集めます。これを描く木（レンダーツリー）と呼びます。
  • 03位置と大きさを測ります。この測り直しが、レイアウト（リフロー）です。
  • 04塗ってから、層を重ねます。層を重ねる作業が、合成（コンポジット）です。

02画面の描き方

リフローは、部屋の測り直しです

家具を動かすと、部屋の広さを測り直すことがあります。幅を読んで、すぐ書くと、その測り直しが繰り返されます。

for (const el of rows) {
  const width = el.offsetWidth; // 幅を聞く。汚れていたら測り直す
  el.style.width = width + 8 + "px"; // すぐ書く。次の読みでまた測る
}

先に全部測ってから書くと、測り直しはまとまります。

03手作業のつらさ

名簿と座席表が、ずれます

配列は名簿、DOMは座席表です。片方だけ直すと、データと画面が食い違います。

  • 01配列だけ消すと、消した人の席が残ります。
  • 02席だけ消すと、名簿にはまだその人がいます。
  • 03正しさが2箇所にあると、次の更新でどちらを信じるか迷います。

03手作業のつらさ

画面は、今のデータの式です

function view(state) {
  // 今のデータなら、画面はこう、と値で返す
  return state.names.map((name) => ({ tag: "li", text: name }));
}

これを UI = f(state) と書きます。画面は今のデータの結果で、仮想DOMはこのやり方の一つです。

04仮想DOM

仮想DOMは、設計図を比べます

本物の家を毎回壊すのではなく、前の設計図と今の設計図を見比べて、違った部屋だけ直します。

  • 01今のデータから設計図を作ります。この作業が render です。
  • 02前の設計図と見比べます。この見比べが diff、再調整（reconciliation）です。
  • 03差だけ本物のDOMを直します。この反映が patch です。
  • 04初回は比べる相手がいないので、設計図をそのまま要素にします。

04仮想DOM

同じ箱は残し、違う箱は捨てます

  • 01タグが同じなら、箱は残します。
  • 02直すのは、変わったラベルと中の文字です。
  • 03タグが違うと、その部分は作り直します。
  • 04入力途中の文字は箱が持っていたので、作り直すと消えます。

最短の直し方を探すわけではありません。同じ種類なら残す、という近道です。

05key

key は座席番号ではなく、名札です

  • 01key は、前と今で同じ項目だと示す名札です。
  • 02無いと、同じ位置を同じものだと思います。
  • 03途中に足すと、入力やチェックが隣の項目へずれます。
  • 04添字は並びが変わらないときだけ使います。別の親へ移った子は、Reactでは key では追いません。

06速さ

「速い」は、比べる相手が要ります

  • 01必要な箇所だけ手で触るより、比べる分だけ増えることがあります。
  • 02毎回作り直すよりは、残せる箱を残しやすいです。
  • 03その後の測り直しも、速さに効きます。
  • 04価値は速さそのものではなく、画面をデータの式で書けることです。

07ほかのやり方

比べないやり方もあります

コンパイルは実行前の翻訳です。 シグナルは、変わると、それを読んだ箇所だけに知らせる値です。

やり方 実行中に木を比べるか 直し方
自分でDOM 比べない 触る場所を自分で書く
React 比べる 設計図の差だけ反映する
Vue 3 比べる。範囲は翻訳時に狭める 設計図の差だけ反映する
Vue Vapor 全部その方式なら比べない 翻訳したDOM操作。3.6の候補版で、選んでオンにする
Svelte 比べない コンパイル時に差分を決める
Solid 比べない 値が変わった箇所だけ更新する

この表は、速さの順位ではありません。2026年10月時点で、Vapor は 3.6 の候補版です。
