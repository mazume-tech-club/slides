DOMと仮想DOMを
体系的に理解する

変数、関数、querySelector がわかれば読めます。

矢印キーで進む。スライドのボタンはデモで、ページは進みません。

00導入

読み終えたら、この4つを言えます

  • 01DOMは、ブラウザがHTMLから作る要素の家系図です。
  • 02画面の更新は、測る、塗る、重ねる、に分かれます。
  • 03仮想DOMは、設計図を比べて、差だけ直すやり方です。
  • 04実行前に直す、変わった値だけ直す、という別のやり方もあります。

01DOMとは

DOMは、要素の家系図です

DOMDocument Object Model。ブラウザがHTMLを読み込んで作る、要素の木構造の地図です。

親がいて、その下に子がいます。画面はこの木を見て描きます。

01DOMとは

HTMLは文字列です。描くのは木です

ファイルに書いてあるHTMLは、ただのテキストです。

ブラウザはそれを読んで家系図にします。私たちが querySelector で触るのは、その木です。

01DOMとは

パースは、文字列を部品に分けることです

  • 01バイト列を文字にする
  • 02タグと文章に切る
  • 03親子の木に積む
  • 04document がその入口になる

01DOMとは

タグが少しくずれても、木はできます

ブラウザは、直しながら読みます。

XMLのように「間違いだから中止」はしません。

01DOMとは

小さいHTMLは、こう木になります


<body>
  <p class="lead">こんにちは</p>
</body>
Document
html
head
body
p.lead
#text こんにちは

01DOMとは

ノードは、木の上の点です

ノード（node）。タグの箱と、中の文字は別の点です。

名前日常の言葉例
Elementタグの箱p、div
Text箱の中の文字こんにちは
Document木全体の入口document
Comment画面に出ないメモHTMLコメント

01DOMとは

children は、子の要素だけです

childNodes は、文字やコメントも含みます。

ソースの改行も、文字のノードになることがあります。

01DOMとは

class は、子どもではありません

属性（attribute）は、箱に貼ったラベルです。

家系図の子としては並びません。classList や getAttribute で触ります。

01DOMとは

探す関数は、木から1件取ります


const list = document.querySelector("#notes"); // 最初の1件を探す

見つからなければ null（何もない、という値）です。API（木を触る関数のこと）の入口です。

01DOMとは

作って、文字を入れて、つなぎます


const list = document.querySelector("#notes"); // リストを探す
const item = document.createElement("li"); // 空の li を作る
item.textContent = "新しい行"; // 文字として入れる
list.appendChild(item); // 末尾につなぐ

01DOMとは

textContent は、文字のまま入れます

innerHTML は、文字列をHTMLとして解釈します。

人からもらった文字列は textContent にします。HTMLとして入れると、意図しないタグになります。

01DOMとは

探した一覧には、2種類あります

  • 01querySelectorAll は、その瞬間のコピーです。
  • 02getElementsByTagName は、その後の変化も映します。
  • 03コピーを静的、映る方をライブと呼びます。

01DOMとは

次のボタンで、見えるものはこれです

  • 01文字を入れて「追加」。末尾に1行増えます。
  • 02その行をクリック。打ち消し線が付きます。
  • 03空のまま「追加」。行は増えません。
  • 04中身は、要素を作って末尾につなぐ操作です。

01DOMとは

押して、行が増えるのを見てください

  • querySelector
  • appendChild

最初の2行はHTMLに書いてあります。増えた行も、クリックで線が付きます。

01DOMとは

クリックは、親へ上がっていきます

たとえ部屋で手を挙げると、その階の人にも聞こえます。これをバブリング（bubbling、親へ上がること）と呼びます。

click は上がります。

01DOMとは

だから、親がまとめて聞けます


list.addEventListener("click", (event) => {
  const item = event.target.closest("li"); // 近い li を探す
  if (!item || !list.contains(item)) return; // 外なら無視
  item.classList.toggle("done"); // 打ち消し線
});

これをイベント委譲（親が子の分まで聞くこと）と呼びます。前のデモは、リストに耳が1つだけです。

01DOMとは

全部の出来事が、上がるわけではありません

  • 01click は親へ上がります。
  • 02focus と scroll は上がりません。
  • 03逆に、親から子へ降りる向きもあります。
  • 04降りる向きをキャプチャ（capture）と呼びます。

02描画

描画は、木を画面の点にすることです

この作業の流れを、パイプライン（pipeline、順番に並んだ作業）と呼びます。

フレームごとに、全部の段が走るとは限りません。

02描画

まず、2つの木を合わせます

DOM

HTMLから作った、要素の木です。

CSSOM

CSS Object Model。CSSから作った、スタイルの木です。

描く木

実際に箱を作るものだけを集めた木です。レンダーツリーとも呼びます。

02描画

そのあと、測って、塗って、重ねます

レイアウト

箱の位置と大きさです。リフロー（測り直し）とも呼びます。

ペイント

色、文字、影を層に塗ることです。

合成

層を重ねて1枚の画面にします。コンポジット（composite）とも呼びます。

02描画

見えない、にも種類があります

  • 01display: none は、箱を作りません。
  • 02visibility: hidden は、場所を取り、見えません。
  • 03opacity: 0 は、場所を取り、透明です。
  • 04head や script も、画面の箱にはなりません。

02描画

リフローは、部屋の測り直しです

たとえ家具を動かしたら、部屋全体の寸法を測り直すことがあります。幅や文字量を変えると、この測り直しが起きやすいです。

02描画

塗るのと、シートをずらすのは別です

ペイントは、壁に色を塗ることです。合成は、透明シートを重ねることです。

transform と opacity は、多くの場合シートを動かすだけで足ります。例外はあるので、DevToolsの層で見ます。

02描画

測って、動かして、また測ると重いです


for (const el of rows) {
  const width = el.offsetWidth; // 幅を聞く。汚れていたら測り直す
  el.style.width = width + 8 + "px"; // 幅を変える。次の読みで再計測
}

この繰り返しをレイアウトスラッシング（layout thrashing、測り直しの連打）と呼びます。getBoundingClientRect() も同じ種類の読みです。

02描画

先に全部測り、あとで動かします


const widths = rows.map((el) => el.offsetWidth); // 先に測る
for (let i = 0; i < rows.length; i++) {
  rows[i].style.width = widths[i] + 8 + "px"; // 測ったあとで書く
}

フレームの先頭では、前回の寸法をまだ読めます。数字の一般論は置きません。見るなら DevTools の Performance です。

03手作業

手順を、全部自分で書きます


function render(state) {
  if (state.status === "loading") {
    root.textContent = "読み込み中"; // 文章だけにする
    return;
  }
  const ul = document.createElement("ul"); // リストを作る
  root.replaceChildren(ul); // 中身をそのリストと入れ替える
}

小さい画面なら、これで足ります。分岐のたびに、DOMへの手順が要ります。

03手作業

名簿と座席表が、別々に古くなります

たとえ名簿から人を消して、座席表を消し忘れると、いない人が座ったままです。

配列から消したのに li が残る。入力欄の文字だけが新しい。正が2箇所にあります。

03手作業

画面は、データの式で書けます


function view(state) {
  // 今の名前ごとに、li の設計図を返す
  return state.names.map((name) => h("li", {}, name));
}

これを UI = f(state) と書きます。仮想DOMは、この式のやり方の一つです。式そのものではありません。

04仮想DOM

仮想DOMは、ただの設計図です

たとえ設計図を2枚比べて、変わった家具だけ直します。仮想DOM（virtual DOM）は、本物の要素の前に置くJavaScriptのオブジェクトです。

04仮想DOM

設計図は、ただのオブジェクトです


const vnode = { tag: "p", props: { class: "lead" }, text: "こんにちは" };
function h(tag, props, ...children) {
  return { tag, props: props ?? {}, children }; // 設計図の1枚を返す
}

JSXは、この設計図をHTML風に書く記法です。DOMそのものではありません。デモは、この形を前回の木と見比べています。

04仮想DOM

作業は、作る、比べる、直す、です

  • 01render。今のデータから、新しい設計図を作ります。
  • 02diff。前の設計図と見比べます。再調整（reconciliation）とも呼びます。
  • 03patch。変わったところだけ、本物のDOMを直します。
  • 04初回だけは比べる相手がいないので、そのまま要素にします。

04仮想DOM

同じ箱は残し、違う箱は捨てます

  • 01タグが同じなら、箱は残します。
  • 02直すのは、変わったラベルと文字です。
  • 03タグが違うなら、その部分は作り直します。
  • 04入力途中の文字は、箱が持っていたので消えます。

これは最短の直し方の証明ではありません。ライブラリが選んだ規則です。

04仮想DOM

key は、座席ではなく名札です

keyリストの各項目に付ける、前後で同じものだと示す名前です。並べ替えても、名札の人が自分のチェックを持っていきます。

04仮想DOM

名札がないと、席の位置で同一視します

  • 01多くの実装は、同じ位置の子を同じものだと思います。
  • 02途中に足すと、隣の項目の入力がずれます。
  • 03配列の添字は、並びが変わらないときだけ安全です。
  • 04Reactでは、別の親へ移った子は key では追いません。

04仮想DOM

最小の手数を探すと、重いです

木を最小の手数で別の木へ変える計算は、一般的な方法だと O(n³) です。

n はノードの数です。手間は、その3乗で増えます。Reactはその最小手数を探しません。

04仮想DOM

Reactの近道は、2つの仮定です

  • 01手間は O(n)。ノードの数にほぼ比例します。
  • 02型が違う要素は、別の木を生む、と仮定します。
  • 03key で、安定な子を示せると仮定します。
  • 04今の実装は Fiber。仕事を小分けにして進める仕組みです。

仮定の説明は React の reconciliation 文書です。リストと key の今の説明は react.dev です。

06速さ

「速い」は、比べる相手が要ります

  • 01必要な場所だけ手で触るより、比べる分だけ増えることがあります。
  • 02毎回捨てて作るよりは、残せる箱を残しやすいです。
  • 03その後の測り直し（レイアウト）も、速さに効きます。
  • 04React Compiler は計算の再利用です。仮想DOMは残ります。

06速さ

価値は、画面を式で書けることです

  • 01「今のデータなら、画面はこう」と書けます。
  • 02更新の抜けを、比べる規則に任せられます。
  • 03同じ木を、ブラウザ以外にも渡せます。
  • 04React Native は、その木をスマホの部品に写します。

07ほかのやり方

Svelteは、実行前に直し方を決めます

コンパイル（compile）は、実行前に別のプログラムへ翻訳することです。

  • 01変わった箇所を、DOMへ書くコードに翻訳します。
  • 02実行中に、設計図の木を丸ごと比べません。
  • 03$state は関数ではなく、翻訳機への印です。
  • 04リストの名札は、each のキー式で示します。

07ほかのやり方

Solidは、変わった値の場所だけ直します

  • 01部品の関数は、最初の1回だけ実行されます。
  • 02シグナル（signal）は、変わると読んだ箇所へ知らせる値です。
  • 03知らせを受けた文字や属性だけが更新されます。
  • 04For は、値の同一性で要素を動かせます。

07ほかのやり方

Vue 3の安定版は、設計図を比べます

テンプレート（HTML風に書いた画面）を、設計図を返す関数にします。

翻訳機が「ここは動かない」と印を付けて、比べる範囲を狭めます。設計図をやめたわけではありません。

07ほかのやり方

Vaporは、選んで使う別の方式です

  • 01実行前に、DOMを直接直すコードへ翻訳します。
  • 02全部その方式なら、設計図の部品を読み込みません。
  • 032026年10月時点で、Vue 3.6 はリリース候補です。
  • 04標準ではオフです。オプトイン（自分でオンにする）です。

速度の比較値は載せていません。出典は Vue 3.6.0-rc.1 のリリースノートです。

07ほかのやり方

直し方の違いだけを並べます

やり方 実行中に木を比べるか 直し方
自分でDOM 比べない 触る場所を、自分で書く
React 比べる 設計図の差だけ反映する
Vue 3 安定版 比べる。範囲は翻訳時に狭める 設計図の差だけ反映する
Vue Vapor 全部その方式なら比べない 翻訳したDOM操作。3.6の候補版
Svelte 比べない コンパイル時に差分を決める
Solid 比べない 値が変わった箇所だけ更新する

この表は、速さの順位ではありません。

07ほかのやり方

数字ではなく、読み方で選びます

  • 01画面の状態が多いなら、式で書く方が抜けが少ないです。
  • 02実行時の仕組みを小さくするなら、Svelte か Solid です。
  • 03Vapor は正式版の前の候補なので、試すときに選びます。
  • 04どのやり方でも、測り直しの設計は残ります。

08まとめ

もう一度、この4つです

  • 01DOMは、HTMLから作った要素の家系図です。
  • 02家具を動かすと、部屋を測り直すことがあります。
  • 03仮想DOMは、設計図の差だけを直します。
  • 04key は速さのスイッチではなく、項目の名札です。
